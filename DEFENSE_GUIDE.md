# 🎓 Руководство для защиты курсового проекта «Lumen — Habit & Sleep Tracker»

Этот документ подготовлен специально для защиты перед комиссией: здесь собраны готовая речь, архитектура, разбор базы данных для показа в **phpMyAdmin**, пошаговый сценарий демонстрации API в **Bruno**, устройство интеграции с **Google Gemini API** и ответы на частые вопросы преподавателей.

---

## 1. Краткая визитка проекта (вступительное слово на 1–2 минуты)

> **Тема проекта:** Веб-приложение для трекинга привычек и анализа качества сна с интеллектуальным AI-консультантом **«Lumen — Habit & Sleep Tracker»**.
>
> **Проблема:** Большинство трекеров привычек и трекеров сна существуют раздельно. Человек видит, что «сорвал привычку», но не видит первопричину — накопившийся недосып или сбитый режим отхода ко сну.
>
> **Решение:** **Lumen** объединяет ежедневный трекинг привычек (стрики, категории, 16-недельная тепловая матрица активности) и аналитику сна (длительность, качество 1–5, индекс регулярности отхода ко сну) на единой платформе, а встроенный **AI-консультант на базе Google Gemini** анализирует корреляцию между сном и дисциплиной и выдаёт персональные рекомендации.

### Технологический стек
| Уровень | Технологии |
| :--- | :--- |
| **Frontend (SPA)** | React 19, Vite 8, Tailwind CSS 4, Framer Motion, Recharts, Lucide Icons, дизайн-система **Liquid Glass** (3 темы: Vision Dark, Vision Light, Aurora) |
| **Backend (REST API)** | PHP 8.3/8.4, Laravel 13, Laravel Sanctum (Bearer-токены), Eloquent ORM |
| **База данных** | MySQL 8.4 (управление через **phpMyAdmin** в Open Server Panel 6) |
| **Внешний ИИ-сервис** | Google Gemini Interactions API (`gemini-3.8-flash` с резервным каскадом `gemini-3.5-flash-lite` / `gemini-3.1-flash-lite`) |
| **Тестирование API** | Bruno (`bruno_collection/`) + автотесты PHPUnit (18 Feature-тестов) |

## 2. Архитектура приложения (Клиент–Сервер, REST API, SPA)

Проект построен по классической **клиент-серверной архитектуре** с полным разделением представления (Frontend SPA) и бизнес-логики (Backend REST API):

```
┌──────────────────────────────────────────────────────────────────────┐
│  FRONTEND — React 19 SPA (http://localhost:5173)                     │
│  • Компоненты: HabitsDashboard, SleepDashboard, AiAdvisorWidget      │
│  • HTTP-клиент: src/lib/api.js (Authorization: Bearer <token>)       │
│  • Vite Dev Proxy: /api, /sanctum ──► http://habit-sleep-tracker.local│
└──────────────────────────────────┬───────────────────────────────────┘
                                   │ JSON over HTTP (REST)
                                   ▼
┌──────────────────────────────────────────────────────────────────────┐
│  BACKEND — Laravel 13 REST API (http://habit-sleep-tracker.local)    │
│  1. Routing (routes/api.php) + Middleware (auth:sanctum, throttle)   │
│  2. FormRequests (валидация входных данных, сообщения на русском)    │
│  3. Policies (HabitPolicy, SleepLogPolicy — защита чужих записей)    │
│  4. Controllers (тонкие контроллеры: Auth, Habit, Sleep, AiAdvice)   │
│  5. Services (бизнес-логика):                                        │
│     • StreakService — расчёт текущего и рекордного стрика            │
│     • SleepAnalyticsService — средние показатели и регулярность сна  │
│     • ActivityMatrixService — тепловая карта активности за 16 недель │
│     • AiService — сбор контекста + запрос к Google Gemini + Fallback │
│  6. Resources (HabitResource, SleepLogResource — единый формат JSON) │
└───────────────┬──────────────────────────────────────┬───────────────┘
                │ Eloquent ORM (PDO MySQL)             │ HTTPS REST (JSON Schema)
                ▼                                      ▼
┌──────────────────────────────────┐   ┌───────────────────────────────┐
│  MySQL 8.4 (habit_sleep_tracker) │   │  Google Gemini API            │
│  Визуализация: http://phpmyadmin │   │  Персональный AI-консультант  │
└──────────────────────────────────┘   └───────────────────────────────┘
```

### Ключевые архитектурные решения, которые стоит отметить комиссии:
1. **Stateless-авторизация через Bearer-токены (`Laravel Sanctum`):** при входе (`/api/auth/login` или `/api/auth/demo`) сервер создаёт токен в таблице `personal_access_tokens`. Клиент сохраняет его в `localStorage` и передаёт в заголовке `Authorization: Bearer <token>`. Это позволяет одинаково удобно работать и из браузера (SPA), и из API-клиентов (**Bruno**), и из мобильных приложений.
2. **Сервисный слой (`app/Services/`):** контроллеры не содержат сложных вычислений. Вся предметная логика вынесена в отдельные сервисы (`StreakService`, `SleepAnalyticsService`, `ActivityMatrixService`, `AiService`), что упрощает модульное и интеграционное тестирование.
3. **Политики доступа (`app/Policies/`):** каждый запрос на изменение или удаление привычки/сна проверяется через `Gate::authorize()`, поэтому пользователь физически не может изменить или удалить чужую запись (вернётся `403 Forbidden`).

## 3. Структура базы данных и связи таблиц (что показать в phpMyAdmin)

Откройте **phpMyAdmin** по адресу: **[http://phpmyadmin](http://phpmyadmin)** (логин `root`, пароль пустой) и выберите базу данных **`habit_sleep_tracker`**.

### Основные таблицы предметной области:

| Таблица | Назначение | Ключевые поля и ограничения |
| :--- | :--- | :--- |
| **`users`** | Пользователи системы | `id`, `name`, `email` (`UNIQUE`), `password` (bcrypt), `role` (`user` / `admin`). Сидер создаёт демо-пользователя **Aurora** (`demo@habit.local`) и администратора (`admin@habit.local`). |
| **`categories`** | Справочник категорий привычек | `id`, `title` (`UNIQUE`), `icon`, `color` (HEX). Примеры: *Здоровье*, *Осознанность*, *Спорт*, *Сон*, *Фокус*. |
| **`habits`** | Привычки пользователя | `id`, `user_id` (`FK → users.id ON DELETE CASCADE`), `title`, `target_frequency` (1–7 дней/нед.), `streak_count` (текущий стрик), `best_streak` (лучший стрик), `accent`. |
| **`category_habit`** | Связующая таблица (pivot) привычек и категорий | `habit_id` (`FK → habits.id`), `category_id` (`FK → categories.id`), составной индекс `UNIQUE(habit_id, category_id)`. Реализует связь **Многие-ко-Многим (M:N)**. |
| **`habit_logs`** | Журнал ежедневных выполнений привычек | `id`, `habit_id` (`FK → habits.id`), `user_id` (`FK → users.id`), `completed_at` (`DATE`), `status`. Составной `UNIQUE(habit_id, completed_at)` гарантирует отсутствие дублей за один день. |
| **`sleep_logs`** | Дневник сна пользователя | `id`, `user_id` (`FK → users.id`), `bed_time` (`TIME`), `wake_time` (`TIME`), `duration_minutes` (`INT`), `quality_rating` (`1..5`), `notes`, `date` (`DATE`). Ограничение `UNIQUE(user_id, date)` — одна запись сна на дату. |
| **`personal_access_tokens`** | Токены авторизации Sanctum | Хранит SHA-256 хеши выданных Bearer-токенов. |

### Схема связей (ER-модель для ответа комиссии):
- **`users` 1 ──► N `habits`** (Один пользователь владеет множеством привычек; при удалении пользователя каскадно удаляются его привычки).
- **`habits` M ◄──► N `categories`** через таблицу **`category_habit`** (У одной привычки может быть несколько категорий, и в одну категорию входит много привычек).
- **`habits` 1 ──► N `habit_logs`** (История отметок выполнения по дням для расчёта стриков и тепловой матрицы).
- **`users` 1 ──► N `sleep_logs`** (История ночного сна пользователя).

> 💡 **Что показать в phpMyAdmin на защите:**
> 1. Вкладку **«Структура»** базы `habit_sleep_tracker` — 11 таблиц, созданных миграциями Laravel.
> 2. Вкладку **«Дизайнер» (Designer)** — наглядная схема связей внешних ключей.
> 3. Таблицу **`sleep_logs`** и **`habit_logs`** — показать реальные демо-данные за последние 30 дней, сгенерированные сидером `TrackerSeeder`.

## 4. Демонстрация API через Bruno (`bruno_collection/`)

В корне проекта находится готовая коллекция **`bruno_collection/`**.

### Как открыть перед комиссией:
1. Запустите **Bruno** → нажмите **Open Collection** → выберите папку `C:\OSPanel\home\habit-sleep-tracker\bruno_collection`.
2. В правом верхнем углу Bruno выберите окружение **`Local (OSPanel)`** (`baseUrl = http://habit-sleep-tracker.local`).

### Сценарий демонстрации (7 последовательных шагов):

1. **`1. Авторизация демо-пользователя (POST /api/auth/demo)`**
   - Нажмите **Send**. Сервер вернёт `200 OK`, профиль пользователя `Aurora` и Bearer-токен.
   - Обратите внимание комиссии на вкладку **Script / Tests**: скрипт `post-response` (`bru.setEnvVar("token", res.getBody().token)`) автоматически сохранил токен в переменную окружения `{{token}}`, а встроенные тесты Bruno проверили ответ.
2. **`2. Список привычек со стриками (GET /api/habits)`**
   - Возвращает привычки пользователя с полями `streak_count`, `best_streak`, `completed_today` и вложенными категориями `categories`.
3. **`3. Создание новой привычки (POST /api/habits)`**
   - Отправляет JSON `{"title": "Вечерняя прогулка без телефона 30 минут", "category_ids": [1, 2]}`.
   - Возвращает `201 Created`. Скрипт автоматически сохраняет `id` созданной привычки в переменную `{{habitId}}`. (В этот момент можно переключиться в phpMyAdmin и показать новую строку в таблице `habits` и привязки в `category_habit`).
4. **`4. Отметка выполнения привычки (POST /api/habits/{{habitId}}/toggle)`**
   - Переключает выполнение созданной привычки за сегодня: `completed_today` становится `true`, а `streak_count` увеличивается на `1`. Повторный вызов снимает отметку.
5. **`5. Статистика и аналитика сна (GET /api/sleep/stats)`**
   - Показывает аналитику за 7 дней: `average_hours`, `average_quality`, `regularity` (% ночей в пределах ±30 минут от медианного времени отбоя) и готовый массив `chart` из 7 точек для графика.
6. **`6. Сохранение записи о сне (POST /api/sleep)`**
   - Отправляет время отбоя `"23:15"` и подъёма `"07:15"` с оценкой `5`.
   - Показывает, что сервер сам корректно считает переход через полночь и записывает `duration_minutes = 480` (8 часов).
7. **`7. Запрос к AI-консультанту (POST /api/ai/advisor)`**
   - Передаёт статистику (`avg_sleep_hours`, `avg_sleep_quality`, `habit_completion_percent`) и вопрос пользователя в Google Gemini.
   - Возвращает живой структурированный ответ на русском языке: `reply`, массив `insights`, массив `recommendations` и итоговый балл `score`.

## 5. Как работает связка с Google Gemini API и какую пользу даёт проекту

### Техническая реализация (`app/Services/AiService.php` и `app/Http/Controllers/Api/AiAdviceController.php`):
1. **Сбор контекста (`buildContext`):** когда пользователь обращается к `POST /api/ai/advisor`, бэкенд объединяет метрики с фронтенда с актуальными данными из MySQL: список конкретных привычек пользователя с их текущими стриками, процент выполнения за 7 дней, среднюю продолжительность, качество и регулярность сна.
2. **Системный промпт (`ADVISOR_SYSTEM_PROMPT`):** задаёт модели роль персонального консультанта *Lumen AI*, требует опираться строго на цифры пользователя, не ставить медицинских диагнозов и отвечать лаконично на русском языке.
3. **Structured Output (JSON Schema):** запрос отправляется в Google Gemini Interactions API (`POST https://generativelanguage.googleapis.com/v1beta/interactions`) с заголовком `x-goog-api-key` и строгой JSON-схемой `response_format` (`reply`, `insights[]`, `recommendations[]`, `score`). Это гарантирует, что нейросеть всегда возвращает валидный JSON нужной структуры, который сразу рендерится в карточках React-интерфейса.
4. **Трёхуровневая отказоустойчивость (Graceful Degradation):**
   - **Уровень 1:** запрос к основной модели `gemini-3.8-flash`.
   - **Уровень 2:** если основная модель перегружена (`HTTP 503 / 429`), сервис прозрачно переключается на резервные модели `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite`.
   - **Уровень 3:** если отсутствует интернет или API-ключ, срабатывает детерминированный локальный алгоритм (`advisorFallback`), рассчитывающий балл и рекомендации по формулам сна и привычек. Приложение **никогда не падает с ошибкой 500** на защите.

### Польза для пользователя и проекта:
- Превращает пассивный дневник («просто таблицы и графики») в **активную систему поддержки принятия решений**.
- Находит неочевидные для пользователя связи: например, указывает, что просадка утренних привычек вызвана падением регулярности отхода ко сну ниже 70%, и предлагает привязать вечернее чтение к фиксированному времени.

## 6. Быстрые ответы на возможные вопросы комиссии

- **Вопрос:** *Как рассчитывается длительность сна, если человек лёг до полуночи (23:15), а встал утром (07:15)?*
  **Ответ:** В модели `SleepLog::minutesBetween()` время переводится в минуты от начала суток. Если время подъёма меньше или равно времени отбоя, к нему прибавляется `24 * 60` (1440 минут), поэтому переход через полночь всегда считается корректно.
- **Вопрос:** *Как считается регулярность сна (`regularity`)?*
  **Ответ:** В `SleepAnalyticsService` вычисляется медианное время отхода ко сну за 7 дней (с учётом сдвига полуночи). Ночь считается регулярной, если отклонение от медианы не превышает `±30 минут`. Итоговый процент — доля таких ночей за неделю.
- **Вопрос:** *Почему API-ключ Gemini хранится на бэкенде в `.env`, а не вызывается напрямую из React?*
  **Ответ:** Во-первых, для безопасности: ключи в браузере легко перехватить через DevTools. Во-вторых, бэкенд обогащает запрос данными из БД MySQL, валидирует схему ответа и ограничивает частоту запросов через `throttle:20,1`.
